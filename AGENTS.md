## Architecture
- Single `Data` object (`lib/types.ts`); `useApp()` exposes `{ S, linked, dbStatus, checkDb, update, toast, notify, modal, form, close, reset }`.
- `components/providers/AppProvider.tsx`:
  - **`update()` deep-clones state (`JSON.parse(JSON.stringify(prev))`)** — required so the persist diff detects changes. Do not revert to a shallow clone.
  - Persist effect mirrors to localStorage and diffs top-level keys vs `prevRef`, writing changed keys via `persistKeys`.
  - Load: when Supabase is configured it is the source of truth — **an empty DB stays empty (no auto-seed)**. It only falls back to localStorage/seed when not configured or on load failure.
- `lib/db.ts`: `TABLE` / `DELETE_COL` / `rowsFor` / `databaseLoad` / `persistKeys`. Delete-then-insert per changed key.
- `lib/seed.ts`: `buildSeed()` used only for local fallback and `Settings → Reset sample data`.
- Forms/modals are generated by `form(title, fields, onOk, okLabel?)` using `FieldDef` (`k,label,type?,req?,v?,o?,full?`).
  Form dialog auto-switches to a wide **two-column "landscape"** layout when a form has > 6 fields; `full:true` spans both columns.
- Feature pages live in `components/features/*` and are registered in `components/features/index.ts` (`VIEWS`); sidebar comes from `NAV`/`ICONS` in `lib/constants.ts`.

## Domain conventions
- Employee salary is **monthly** USD; `gross(e) = e.salary` (`lib/utils.ts`).
- Employee fields: name, role (Job title), dept, type, status, start, salary, email + gender, dob, nationality,
  idNo, contact, placeOfBirth, address, qualification. `idNo`→`id_no`, `placeOfBirth`→`place_of_birth`, `dob` date on write.
- Standard module shape: searchable table + `form(...)` for Add/Edit + row-click detail modal with Edit/Delete.
- Migrations are additive files in `supabase/migrations/`. Apply by running the SQL through `pg` (pooler) with `SUPA_DB_PASSWORD`.
